# Long Run Verified MCP: deployment and acceptance
Current implementation is independent from legacy PersistFlow runs. Use Google Docs as bounded durable ledger with requiredRevisionId; GitHub remains code/evidence authority. The MCP reports caller-provided evidence, not external independent verification. Max 100 runs and 180,000 serialized characters per configured document; archive/rotate by explicit owner operation before capacity. No deletion/reset tool.

## Prerequisites and safe rollout
- Use a dedicated owner-private native Google Doc. Never point at a handoff or business document. Inspect contents and permissions before first write.
- Prefer `LRV_AUTH_MODE=composio`: use a narrowly scoped project API key authorized for proxy execution, actual connected-account ID for the owner Google Drive/Docs account, and its Composio user ID. The proxy calls only the fixed Google Docs document and batchUpdate endpoints; no raw provider tokens are extracted. Confirm that the connected account grants document read/write and that the Docs API is enabled. A Google OAuth provider is supported as an explicit alternative, using its own authorized drive.file grant.
- Set `LRV_DOCUMENT_ID`, `LRV_COMPOSIO_ACCOUNT_ID`, `LRV_COMPOSIO_USER_ID`, `COMPOSIO_API_KEY_FILE` (a mounted read-only secret), `LRV_TOKEN_SHA256` (SHA-256 of a new strong randomly generated MCP bearer), `PORT=3000`, `LRV_BIND_HOST=0.0.0.0` inside an isolated container. Do not copy credentials out of other services.
- Build from the repository root: `docker build -f long-run-verified/Dockerfile -t long-run-verified:<SHA> .`. The container runs unprivileged. Mount only the dedicated secret, do not expose port 3000 publicly; use the existing gateway's private Docker network. Set resource limits and read-only rootfs.
- Preflight the startup read of the exact Drive doc; no bind until successful. Exercise start/checkpoint/status/finish with synthetic test run and verify actual readback and stale-version denial. Retain the receipt. Test restart and status recovery.
- Add a distinct authenticated HTTPS route to the existing gateway only after live Drive preflight. Back up config, validate before reload, confirm pre-existing routes still work, and rollback on regression. Do not overwrite existing sites, stop legacy services or change DNS. Route must rewrite the external path to internal /mcp without redirect.
- Register with Composio Custom MCP using private user ID, final HTTPS URL, API_KEY header scheme. Official API: https://docs.composio.dev/docs/extending-sessions/custom-mcp . Private custom toolkits require the applicable Composio plan. Never substitute project-wide sharing without authorization. The helper `node long-run-verified/register-composio.js --apply` requires `COMPOSIO_ADMIN_API_KEY_FILE` or a dedicated admin key env, `LRV_COMPOSIO_USER_ID`, and `LRV_PUBLIC_URL`. First check existing custom toolkit listing for duplicate. On ambiguous response, inspect current toolkit list before retry. API key entry uses official connect flow.
- Confirm active connection and discovery of all nine tools through Composio, then run a synthetic end-to-end mission and read back its state. A local SDK test alone is not production acceptance.
- Do not claim a longer ChatGPT server timeout or automatic next turn. Workers/automation require separate authorization and configured runtime.

## Rollback
Remove only the new route and container; preserve the ledger and receipts. Revoke new bearer and project credentials if needed. Do not delete legacy PersistFlow state.
